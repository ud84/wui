# WUI: план развития

Рабочий проект роадмапа · 6 сентября 2026 года. Этапы задают порядок приоритетов; даты и номера релизов определяются после оценки объёма работ. Незавершённые пункты описывают предложения, а не обещания доступных возможностей.

## Направление: GUI-библиотека в духе Boost

Исходная идея создателя — сделать «Boost.UI». Развиваем её как инженерный ориентир: обычный C++17, небольшой понятный API, документированные контракты, предсказуемое владение ресурсами, удобное подключение к существующему приложению. Возможное вступление в Boost — отдельное решение на будущее.

Предлагаемое позиционирование:

> WUI — компактная C++17-библиотека для desktop-приложений с общими контролами и темами на Windows, Linux и macOS, прямым управлением интерфейсом из C++ и прозрачными системными зависимостями.

Начальная аудитория: авторы инженерных инструментов, конфигураторов, диагностических утилит и desktop-клиентов с уже существующим C++-ядром. Им важны управляемый размер приложения, возможность разобраться в библиотеке и одинаковая логика UI на трёх ОС. Это гипотеза для проверки на новых интеграциях.

Лёгкие кроссплатформенные GUI уже существуют: например, [FLTK](https://www.fltk.org/) поддерживает Windows, Linux и macOS. Поэтому ценность WUI нужно показывать через сочетание API, темизации, интеграции и реальных приложений. Заявления о превосходстве по скорости или размеру требуют воспроизводимых измерений.

## От чего отталкиваемся

- Общие контролы, темы, локализация и событийная модель; платформенные реализации Windows и Linux, новый экспериментальный macOS-порт.
- В текущей ветке есть macOS integration/smoke-тесты. Корневой CMake пока включает тесты только для Apple; в `.github/workflows` находится workflow публикации документации.
- WUI уже включена в [awesome-cpp](https://github.com/fffaraz/awesome-cpp#frameworks). Следующая задача для этого канала — помочь читателю быстро собрать своё приложение.
- На [сайте проекта](https://libwui.org/main/#used-by) представлены VideoGrace и Decima-8. Это основа для технических разборов применения; опубликованные там показатели нужно дополнить методикой измерения.
- Открытые задачи уже показывают потребности: документация, Linux desktop-интеграция, редактирование текста. Их включаем в общий план.

## Принципы развития

1. **Совместимость API.** Изменения публичных сигнатур требуют конкретной причины, оценки влияния и описания миграции. Для маленьких значимых типов вроде `rect` сохраняем передачу по значению, пока нет обоснованной причины менять контракт. Массовое форматирование оформляем отдельно от исправлений.
2. **Проверяемые контракты.** Описываем владение, время жизни подписок, разрешённые потоки вызова, обработку ошибок, координаты, цвет и текст. Подкрепляем тестами места, где различия бэкендов способны сломать приложение.
3. **Контролируемые зависимости.** Системные и встроенные зависимости перечислены явно. Новая обязательная зависимость должна решать подтверждённую задачу и иметь понятную стоимость сопровождения.
4. **Небольшие законченные изменения.** Одна задача, обозримый PR, проверяемый результат. Новые абстракции сначала проходят проверку на реальном приложении.
5. **Честная поддержка платформ.** Разделяем проверенную конфигурацию, целевую совместимость и известные ограничения. Сборка под архитектуру и запуск на ней — разные проверки.

## Этап 1. Надёжный релиз на трёх платформах

Цель: пользователь может выбрать релиз и понять, где и как он проверен.

- [ ] Довести macOS-порт до релизного состояния: окна и модальность, фокус, клавиатура, IME, clipboard, Retina, ресурсы `.app`, завершение приложения. Отдельно зафиксировать ограничения tray, системных уведомлений и device events. Связано с [#1](https://github.com/intent-garden/wui/issues/1).
- [ ] Добавить CI-сборку библиотеки и примеров на Windows/MSVC, Linux/GCC и macOS/Clang; проверять общий код также Clang на Linux.
- [ ] Выделить общие тесты геометрии, событий и жизненного цикла; добавить платформенные проверки отрисовки и ввода по обнаруженным регрессиям. Сохранить macOS-тесты и sanitizer-прогон.
- [ ] Для GUI-тестов определить окружение: доступный графический сеанс на Windows/macOS и виртуальный X-сервер для подходящих Linux-сценариев. Проверки desktop environment, нескольких мониторов и IME включить в воспроизводимый ручной чеклист, если CI их не покрывает.
- [ ] Воспроизвести и исправить разворачивание окна в Linux: [#25](https://github.com/intent-garden/wui/issues/25). Проверить хотя бы GNOME и KDE, а также XFCE из исходного отчёта.
- [ ] Опубликовать матрицу ОС, архитектур, компиляторов и функций. Для Windows XP/7, старых glibc и macOS 10.15 явно указать, что проверено запуском, а что пока является целевой совместимостью.
- [ ] Согласовать документацию с реализацией: владение `shared_ptr`, подписки, UI-поток, ресурсы, конфигурация, графические координаты и фактическое расположение платформенного кода. Связано с [#82](https://github.com/intent-garden/wui/issues/82).

**Критерий завершения:** зелёные сборки трёх платформ, опубликованные результаты GUI-проверок и ограничения, работающие примеры из тега релиза. Статус macOS повышается после проверки заявленных сценариев; непроверенные архитектуры сохраняют соответствующую отметку.

## Этап 2. От подключения до первого приложения

Цель: разработчик собирает минимальное приложение по документации без помощи автора WUI.

- [ ] Добавить экспортируемую CMake-цель `wui::wui`, установку заголовков и библиотеки, пакет для `find_package(wui CONFIG REQUIRED)` с корректными транзитивными зависимостями.
- [ ] Дать рабочий пример `FetchContent` с закреплённым тегом и отдельный пример использования установленного пакета. Проверять оба из внешнего consumer-проекта в CI.
- [ ] Подготовить короткий RU/EN quickstart для трёх ОС: зависимости, сборка, окно с кнопкой, обработчик события, тема, ресурсы и запуск. Показать структуру небольшого приложения.
- [ ] Выпускать demo-артефакты для заявленных платформ с указанием версии и требований. Для Linux определить базовую систему сборки; для macOS описать статус подписи и способ распространения.
- [ ] Добавить `CONTRIBUTING.md`, шаблоны bug report и PR, правила совместимости и порядок релиза. У новых задач указывать ожидаемое поведение и способ проверки.
- [ ] Выбрать первый пакетный менеджер по запросам пользователей: vcpkg или Conan. Поддержку второго добавлять при наличии спроса и ответственного за рецепт.

**Критерий завершения:** хотя бы два разработчика, ранее не работавших с WUI, собирают своё окно по quickstart; найденные препятствия исправлены. Целевой ориентир — около 10 минут после установки описанных зависимостей, с замером на конкретном окружении.

## Этап 3. Повседневное удобство интерфейса

Цель: обычные экраны приложения требуют меньше вспомогательного кода и ведут себя предсказуемо.

| Приоритет | Работа | Проверяемый результат |
| --- | --- | --- |
| Высокий | Ввод текста: Undo/Redo ([#30](https://github.com/intent-garden/wui/issues/30)), выделение, clipboard, IME, Unicode | Общий набор сценариев редактирования проходит на трёх ОС; ограничения сложных письменностей описаны |
| Высокий | DPI, масштабирование, размеры текста | Перенос окна между мониторами и изменение масштаба сохраняют читаемость, геометрию и точность попадания мышью |
| Высокий | Компоновка: строки, столбцы, отступы, минимальные и предпочтительные размеры | Один прикладной экран переживает resize и смену языка; API дополняет существующее позиционирование через `rect` |
| Высокий | Доступность базовых контролов | Контракт ролей, имён, состояний и действий; проверяемый сценарий с клавиатурой и screen reader для окна, кнопки и поля ввода на каждой платформе |
| Средний | Числовой spinbox поверх текстового ввода | Явные минимум, максимум и шаг; кнопки и клавиатура; колесо меняет значение только при фокусе, без случайного изменения при прокрутке формы |
| Средний | Linux desktop-интеграция: иконка, tray, меню ([#26](https://github.com/intent-garden/wui/issues/26), [#27](https://github.com/intent-garden/wui/issues/27), [#28](https://github.com/intent-garden/wui/issues/28)) | Матрица поведения в выбранных DE, корректная обработка недоступных возможностей |
| Средний | Системные диалоги открытия/сохранения и каталоги данных приложения | Небольшой общий API, примеры обработки отмены и ошибок, проверка на трёх ОС |
| По запросу | Большие списки и таблицы | Сначала профиль прикладного сценария; виртуализация и расширение API по результатам |

Проектирование доступности начинать вместе с контрактами первого этапа: оно может повлиять на API контролов. Расширять набор доступных контролов постепенно, публикуя покрытие.

В начале этого этапа проверить WUI через XWayland в распространённых Wayland-сеансах и перечислить ограничения. Решение о собственном Wayland-бэкенде принять по конкретным блокирующим сценариям и оценке сопровождения.

**Критерий завершения:** прикладной пример с формой, списком, фоновым действием, сохранением настроек и двумя локалями работает на трёх ОС; ключевые сценарии доступны с клавиатуры. Каждое улучшение можно выпускать отдельно.

## Постоянное направление. Применение и рост сообщества

Начинается параллельно со стабилизацией; более широкий анонс привязан к готовому релизу и quickstart.

- [ ] Обновить README и сайт: три платформы с точным статусом, короткий собираемый пример, актуальные скриншоты, системные зависимости и ограничения.
- [ ] Подготовить технический материал о macOS-порте: какие части UI переиспользовались, что потребовало платформенной реализации, как проверялись ввод и рисование.
- [ ] Оформить разборы VideoGrace и Decima-8: задача приложения, причины выбора WUI, ограничения, архитектура интеграции. Показатели размера и производительности сопровождать конфигурацией и методикой.
- [ ] Провести 2–3 внешние пилотные интеграции, фиксируя трудности подключения, недостающие функции и затраты на обновление версии.
- [ ] Поддерживать несколько небольших задач для первого вклада: воспроизводимый bug, пример или исправление документации с понятным критерием приёмки.
- [ ] Снять воспроизводимые показатели: размер минимального приложения, время сборки и старта, память и CPU в покое, отзывчивость списка. Зафиксировать ОС, железо, toolchain, режим сборки и способ линковки. Сравнения с другими библиотеками строить на эквивалентных сценариях.

**Показатели прогресса:** успешное самостоятельное подключение, внешние приложения, повторные вклады, время устранения воспроизводимых регрессий, возможность обновить WUI без переписывания приложения. Звёзды и посещаемость помогают оценивать видимость; эти показатели помогают оценивать полезность.

## Ближайший эксперимент: интерактивное демо на сайте

Первый WASM-бэкенд находится в разработке: Emscripten + Canvas 2D, общие C++-контролы и три существующих примера. Цель — дать посетителю libwui.org попробовать библиотеку прямо в браузере. Критерий готовности: статический пакет демо, проверки Chromium/Firefox/WebKit и опубликованные ограничения. Дальнейшая поддержка браузерных приложений, постоянного хранения и доступности оценивается по результатам этого эксперимента.

## Последующее развитие

Порядок уточняется по обратной связи после первых этапов:

- Согласованная семантика интеграции с внешним event loop и фоновыми задачами — если этого требуют интеграторы.
- Развитие доступности, сложного текста, drag-and-drop, системных меню и уведомлений по опубликованной матрице возможностей.
- Нативный Wayland-бэкенд — после исследования ограничений XWayland.
- Ускоренный рендеринг — когда измерения показывают предел текущего пути и есть воспроизводимая целевая нагрузка.
- Формальное рассмотрение пути в Boost — если это остаётся желанием мейнтейнера, API стабилизирован и есть готовность к отдельной работе над предложением и сопровождением.

Mobile-порты, визуальный дизайнер, множество языковых биндингов и крупная смена модели UI пока не входят в ближайшие этапы: для каждого нужны пользовательский сценарий и ресурс поддержки.

Небольшие улучшения вроде оформления модальных окон ([#41](https://github.com/intent-garden/wui/issues/41)) и цветов messagebox ([#40](https://github.com/intent-garden/wui/issues/40)) можно вести независимо. Spellcheck ([#31](https://github.com/intent-garden/wui/issues/31)) — после базовой надёжности редактирования текста.
