* **Добавлено [Новое, изменено]:**
	- TEXT: класс `wui::text` переработан и поддерживает *clipping* и назначение межстрочного интервала. 
	Добавлен новый класс `wui::text_ex`, который поддерживает clipping и *alpha канал*. Пример в `demo`, 
	текст 'Welcome ...' назначен цвет `#70f5f5f0` для `h1_text`. WIN32 класс `wui::text_ex` использует GDI+, 
	рисование текста отличается от класса `wui::text` небольшими отступами до и после текста линии. 
	Это не влияет на визуальную привлекательность текста.
	
	- TEXT: в классы контролов, где необходимо, добавлены методы  `get_preferred_size()`, что позволяет, 
	если хоть одно окно программы инициализировано, построить свой макет (Layout) или в будущем написать 
	библиотечные. 
	Примеры используют get_preferred_size() для макета кастомных диалогов и частично - расположения контролов.
	
	- TEXT: DEBUG - добавлен `#define _UI_CHECK` (text.hpp). Позволяет визуально проверить занятый текст и заявленный прямоугольник. По умолчанию - undef.	
	
	- win32: для управления созданием и закрытием окон, используется класс **listener** - корректное назначение инстанса графики для измерений текста. При удалении окна, указатель графики переназначается на новое окно. Причина описана [Bug fixes]. Это убирает проблему нарушения памяти программы, если окно было удалено, указатель на графику становится не действительным.
	
	- `color`: класс переработан под формат `RGBA`. Прозрачность в данный момент работает только в классе text_ex.
	Изменения в `wui::color` не влияют на формат цвета `wui::*.json BGRA`, а добавление альфа канала меняет 
	только отрисовку текста в классе `wui::text_ex`. Так же это может быть доступно для `round box` и linux graphic.
	
	- `menu`: для устранения ошибок заполнения структуры `menu_item` пользователем библиотеки, создан класс, 
	видимый пользователю библиотеки, который и используется в программах. Таким образом случайное заполнение 
	лишними полями структуры невозможно. Код заполнения меню совместим с ранними версиями примеров библиотеки.
	
	- Message: `class message` использует `get_preferred_size()` для вычисления размеров окна и расположения контролов.
	В примерах отображение текста сообщения теперь работает. 
	
	- Добавлены новые методы классу `wui::graphic`.
	
	- файл `listener.h` переименован в `listener.hpp`
	
	- 'wui/examples' доработаны с использованием новых исправлений и добавлений.
	Для настройки controls при формировании макета окна рекомендуется использовать:
	подписку на событие `wui::internal_event_type::window_created` (например, диалоговое окно).
	и/или подписку на событие `wui::internal_event_type::size_changed`.
	
	- в проект добавлен файл `CMakeSettings.json`, позволяющий удаленную отладку linux проектов в wsl2.
	
	- изменен `build.sh`. Предлагается собирать проект в каталоге build.
	
	- `examples/**/CMakeLists.txt` добавлено копирование assets (каталоги res) при компиляции программ.
	
* **Добавлено [Новое, экспериментальное]:**
	- WIN32: базовая поддержка изменения DPI. 
	Добавлен `wui::framework::init()` вызов `SetProcessDpiAwarenessContext`, окно автоматически 
	подстраивается под DPI, так же окнам посылается WM_DPICHANGED, который можно использовать для изменения состояний окна и контролов.
	https://learn.microsoft.com/ru-ru/windows/win32/api/winuser/nf-winuser-setprocessdpiawarenesscontext

	- `wui::menu` Item `id` для пользователя библиотекой теперь используется для идентификации пункта меню, если потребуется, в отличии от номера, зависящего от порядка открытия подменю.
	
	- `wui::window` : `wui::window:: bool root_window` теперь назначается первому открытому окну. 
	Метод `void set_root_window()` удален. Так же, поле `root_window` используется для алгоритма закрытия всех окон.
	
	- Курсоры и изображения при обновлении/движении курсора мышки загружаются/устанавливаются 
	только по необходимости изменения. Актуально для X11, оптимизация использования CPU и fs.

	- Деструкторы объявлены виртуальными, там, где в классах используются виртуальные функции. 
	Для классов, использующих `std::enable_shared_from_this` отсутствие виртуальности деструктора не критично, 
	однако, не мешает.

* **Исправлено [Bug fixes]**	
  - std::weak_ptr::lock() : часть кода библиотеки не использовала создания shared_ptr,
  а использовалась конструкция `if(p_.lock()) {p = p_.lock(); // use p}}`, что противоречит weak_ptr. 
  Корректный способ: `auto p = p_.lock(); if(p) { //use p }`. 
  Примеры: `PluggedWindow:Unplug(), PluggedWindow:Init()`. 
  Также `class input` weak ptr не проверялся на доступность `input::buffer_copy()`. 
  Исправлено.
  
* **Исправлено, тестовое [fixes]**	
  - Graphic: WIN32 GDI+ `DrawRoundBox()` для `Round != 0` рисовал смещенные линии. 
  Тестовое исправление.
  
  - std::weak_ptr::lock() : 
  Часть старого кода проверяет на существование shared_ptr `if(p_.lock()) { //далее код не использующий p}`.
  Требуется анализ, использовать ли в этом случае `if(p_.expired()) {}`, что производительнее, или
  делать замок `auto p = p_.lock(); if(p) { //далее код косвенно использующий p}`.  
  Конструкции, типа `if(p && !p_->p_().expired()) { // p_->p_() используется далее косвенно с проверкой !expired() }`вероятно, допустимы. Или ... необходимо делать замок `if(p) { auto p2 = p->p_().lock(); if(!p2) { ... } }`.В очевидных случаях производительнее использовать `.expired()`.
  Тестовое исправление.
  
  - **WIN32**: выход из цикла сообщений `while (GetMessage())`. При закрытии главного окна в примерах вызывается
  `wui::framework::stop();` при этом происходит *выход* из цикла сообщений `call PostQuitMessage()`. 
  Если, открыты дополнительные окна, (физическое окно), деструктор окна вызывается (при раскручивании стека OS) функции выхода из программы xxx_exit(). В этом случае сообщения окну `WM_DESTROY, WM_NCDESTROY` уже не приходят от деструктора `window::~window()` при вызове `DestroyWindow()`. Кроме того, при выходе вызываются деструкторы и для статических singleton в разных модулях в *непредсказуемом порядке*.
  Сейчас сообщение PostQuitMessage() вызывается последним окном в коде WM_NCDESTROY (можно в WM_DESTROY, пока нет в библиотеке child window). 
  Закрытие окон пользовательском коде осуществляется `wui::window->close()`. Доступ к реальному вызову `wui::window->_destroy()` закрыт,
  теперь `virtual wui::window->destroy()` вызывает `wui::window->close()` для совместимости. 
  WIN32: `wui::listener`как singleton не разрушается до закрытия окон. Так же он используется для корректного 
  назначения `tm_graphic` при разрушении физических окон.
  Тестовое исправление. Требует тестирования в примерах, где создаются дополнительные "физические" окна 
  (протестирована на примере *simple*).
  
  - При уничтожении физических вторичных окон указатель на статическую переменную 'tm_graphic' становился не действительным, пока не создано новое окно. Установка 'tm_graphic = nullptr' при разрушении окна решает только проблему нарушения доступа к памяти, однако, измерение текста становится недоступным для распространенного способа инициализации и добавления контролов в примерах до создания окна (если нет `parent window` и `transient window`). 
  Если у окна есть физический `transient window`, надо писать дополнительный код. Например, нельзя вычислить размер окна `wui::message` и других диалоговых окон. 
  Решение проблемы - поиск любого физического окна и установка 'tm_graphic' возможна
  с помощью `wui::listener`. В Linux listener добавлен.  В win32, аналогичный linux X11 код и создание singleton 
  `listener`, становится проблемой, связанной с порядком уничтожения статических не простых 
  структур в разных модулях и т.п., так как в `wui::framework::stop()` в win32 останавливал цикл сообщений и 
  OS сама чистила за `wui`, запуская деструкторы, окна уже не получали сообщений (WM_DESTROY, WM_NCDESTROY).
  Тестовое исправление.
  
* **Оптимизация**
	- приложения из примеров открываются заметно быстрее.
	
	- Курсоры и изображения при обновлении/движении курсора мышки загружаются/устанавливаются 
	только по необходимости изменения. Актуально для X11, оптимизация использования CPU и fs.
	
	- везде, где в аргументах использовался `const wui::rect r`, копирование (частые вызовы методов при инициализации, `redraw()` и тп), заменено на константную ссылку `const wui::rect& r`. 
	Проверена возможная несовместимость с вызовом из старого пользовательского кода `list::draw_callback_(...)`, интересно, что std::bind(), копируя аргументы, не замечает разницы и код работает.
	
	- Косметические изменения - неизменяемые стековые значения в методах и функциях, в аргументах объявлены константами, что помогает компилятору в оптимизации и устраняет случайные алгоритмические ошибки при программировании.

	- Добавлены в соответствие стандарту: `override` (упрощает поиск ошибок), `[[nodiscard]], [[deprecated]]` и тп
	
	- `framework_lin_impl::run()` в цикле ожидания выхода из программы теперь используется wait() по событию.
